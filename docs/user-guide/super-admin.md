## 功能概述

超级管理员（Super Admin）是 ERP 系统中负责平台级管理的特殊角色。与普通租户管理员不同，超级管理员拥有跨租户管理能力，可以对平台上所有租户进行创建、配置、监控和维护操作。

### 核心功能

| 功能模块 | 说明 |
|----------|------|
| **租户管理** | 创建、编辑、查看、删除租户；管理租户生命周期 |
| **订阅管理** | 变更租户的订阅计划（Free/Basic/Pro/Enterprise）和资源配额 |
| **状态管理** | 暂停、激活租户；支持单个和批量操作 |
| **统计报表** | 查看平台级统计数据、增长趋势、计划和状态分布 |
| **审计日志** | 查看所有管理操作记录，支持筛选、搜索和导出 |

### 访问路径

超级管理员面板独立于主应用，通过以下路径访问：

- **租户管理**：`/super-admin/tenants`
- **统计报表**：`/super-admin/stats`
- **审计日志**：`/super-admin/audit-logs`

### 权限说明

- 超级管理员属于特殊的"系统租户"（System Tenant）
- 只有拥有 `SUPER_ADMIN` 角色的用户才能访问超级管理员面板
- 普通租户的管理员、销售、仓库、财务等角色**无法**访问超级管理员页面
- 未登录用户访问超级管理员页面会被自动重定向到登录页
- 超级管理员**只能**查看租户元数据和配置信息，**不能**直接访问租户的业务数据（订单、产品等）

## 登录方式

超级管理员使用与普通用户相同的登录页面进行身份验证，无需切换到专用的登录入口。

### 登录步骤

1. 打开 ERP 系统登录页面（默认地址：`http://localhost:3000/login`）
2. 在**用户名**字段输入超级管理员账号
3. 在**密码**字段输入超级管理员密码
4. 点击**登录**按钮

> **默认超级管理员账号**
>
> | 字段 | 值 |
> |------|------|
> | 用户名 | `superadmin` |
> | 密码 | `superadmin123` |
>
> **安全提示**：首次登录后请立即修改默认密码。

### 登录后的跳转

- 登录成功后，系统会自动识别超级管理员身份
- 您可以通过侧边栏导航或直接输入 URL 访问超级管理员面板
- 系统通过 JWT（JSON Web Token）验证您的身份，Token 中包含系统租户标识

### 身份验证机制

超级管理员的身份验证分为两层：

| 验证层 | 检查内容 | 说明 |
|--------|----------|------|
| **第一层** | 租户ID检查 | 确认用户属于系统租户（`00000000-0000-0000-0000-000000000000`） |
| **第二层** | 角色权限检查 | 确认用户拥有 `SUPER_ADMIN` 角色或 `tenant:*` 权限 |

两层验证通过后才能访问超级管理员功能。

## 租户管理操作指南

### 租户列表

租户列表是超级管理员面板的主页面，展示平台上所有租户的概览信息。

**页面路径**：`/super-admin/tenants`

#### 列表功能

| 功能 | 说明 |
|------|------|
| **分页显示** | 每页 20 条记录，支持翻页 |
| **实时搜索** | 按租户名称或邮箱搜索 |
| **状态筛选** | 按 Active（活跃）、Suspended（暂停）、Inactive（停用）、Trial（试用）筛选 |
| **计划筛选** | 按 Free、Basic、Pro、Enterprise 筛选 |
| **排序** | 支持按名称、邮箱、计划、状态、创建日期排序 |
| **批量选择** | 勾选多个租户进行批量操作 |

#### 表格列说明

| 列名 | 说明 |
|------|------|
| **Name（名称）** | 租户名称，可点击进入详情页 |
| **Email（邮箱）** | 联系人邮箱 |
| **Plan（计划）** | 当前订阅计划，以彩色标签显示 |
| **Status（状态）** | 当前状态，以彩色标签显示 |
| **Created（创建时间）** | 租户创建日期 |
| **Actions（操作）** | 操作下拉菜单 |

#### 单个租户操作菜单

点击租户行右侧的操作按钮，展开操作菜单：

| 操作 | 说明 |
|------|------|
| **View（查看）** | 进入租户详情页 |
| **Edit（编辑）** | 打开编辑租户弹窗 |
| **Suspend（暂停）** | 暂停该租户（仅活跃租户显示） |
| **Activate（激活）** | 激活该租户（仅暂停租户显示） |
| **Delete（删除）** | 永久删除该租户 |

### 创建租户

创建新租户以在平台上注册一个新的业务实体。

#### 操作步骤

1. 在租户列表页面，点击页面右上角的 **Create Tenant（创建租户）** 按钮
2. 在弹出的创建租户对话框中填写以下信息：

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| **Name（名称）** | 是 | 租户名称 | 深圳科技有限公司 |
| **Code（编码）** | 是 | 租户唯一编码（不可重复） | shenzhen-tech |
| **Contact Email（联系邮箱）** | 否 | 联系人邮箱 | admin@example.com |
| **Plan（计划）** | 是 | 选择订阅计划 | Basic |
| **Trial Days（试用天数）** | 否 | 试用期天数（最大 90 天） | 14 |

3. 检查填写信息无误后，点击 **Create（创建）** 按钮
4. 系统会提示创建成功，新租户将出现在列表中

#### 注意事项

- 租户编码（Code）在整个平台中必须唯一，创建后不可修改
- 如果设置了试用天数，租户初始状态为 Trial（试用）
- 创建操作会被记录到审计日志中

### 查看租户详情

租户详情页展示单个租户的完整信息，包括基本信息、订阅状态、配额使用、配置参数和变更历史。

**1. 基本信息**

| Code（编码） | 唯一识别码 |
| Short Name（简称） | 租户简称 |
| Contact Email（联系邮箱） | 主联系人邮箱 |
| Contact Name（联系人） | 主联系人姓名 |

| Address（地址） | 办公地址 |

### 删除租户

永久删除一个租户及其所有关联数据。此操作**不可恢复**。

#### 操作步骤

1. 进入方式二选一：
   - 在租户列表页面，点击操作菜单中的 **Delete（删除）**
   - 在租户详情页面，点击 **Delete（删除）** 按钮
2. 系统弹出确认对话框，显示警告信息："This action is permanent"
3. **二次确认**：输入租户名称以确认删除意图
4. 点击 **Delete（删除）** 执行删除

#### 注意事项

- 删除操作是永久性的，**无法撤销**
- 删除前请确认该租户的所有数据已备份或不再需要
- 系统租户（System Tenant）不可删除
- 删除操作会被记录到审计日志中

> **警告**：删除租户将同时删除该租户下的所有用户、产品、订单等业务数据。请谨慎操作。

## 订阅管理操作指南

### 变更订阅计划

为租户变更订阅计划，调整其可用功能和资源限制。

#### 可用的订阅计划

| 计划 | 说明 | 适用场景 |
|------|------|----------|
| **Free** | 免费版，基础功能，有限配额 | 试用和评估 |
| **Basic** | 基础版，满足小型企业需求 | 小型企业 |
| **Pro** | 专业版，扩展功能和更高配额 | 中型企业 |
| **Enterprise** | 企业版，完整功能和最高配额 | 大型企业 |

#### 操作步骤

1. 进入租户详情页
2. 点击 **Change Plan（变更计划）** 按钮
3. 在弹出的对话框中：
   - 从下拉菜单选择新的订阅计划
   - 在 Notes（备注）字段输入变更原因（可选）
4. 点击 **Confirm（确认）** 执行变更

#### 变更规则

| 变更类型 | 生效时间 | 说明 |
|----------|----------|------|
| **升级**（如 Basic → Pro） | 立即生效 | 新功能和配额立即可用 |
| **降级**（如 Pro → Basic） | 计费周期结束时 | 当前周期内继续享受原计划权益 |

#### 注意事项

- 不能变更为与当前相同的计划
- 变更记录会显示在租户详情页的"订阅变更历史"中
- 变更操作会被记录到审计日志中

### 更新配额

调整租户的资源使用上限，包括用户数、产品数和仓库数。

#### 操作步骤

1. 进入租户详情页
2. 点击 **Update Quota（更新配额）** 按钮
3. 在弹出的对话框中修改以下配额：

| 配额字段 | 说明 | 约束 |
|----------|------|------|
| **Max Users（最大用户数）** | 允许创建的最大用户数量 | 正整数 |
| **Max Products（最大产品数）** | 允许创建的最大产品数量 | 正整数 |
| **Max Warehouses（最大仓库数）** | 允许创建的最大仓库数量 | 正整数 |

4. 在 Reason（原因）字段输入调整原因（可选）
5. 点击 **Update（更新）** 确认修改

#### 注意事项

- 配额更新**立即生效**
- 新配额值不应低于租户当前的实际使用量
- 配额更新操作会被记录到审计日志中

> **提示**：可以在租户详情页的"配额使用"区域查看当前使用情况，据此合理调整配额。

## 状态管理操作指南

### 租户状态说明

| 状态 | 标签颜色 | 说明 |
|------|----------|------|
| **Active（活跃）** | 绿色 | 正常运行，所有功能可用 |
| **Trial（试用）** | 蓝色 | 试用期内，功能受限 |
| **Suspended（暂停）** | 红色/橙色 | 已暂停，租户用户无法登录和使用系统 |
| **Inactive（停用）** | 灰色 | 已停用 |

---

### 暂停租户

暂停一个活跃的租户，使其所有用户无法访问系统。

#### 操作步骤（单个暂停）

1. 在租户列表页面，点击目标租户行的操作按钮
2. 选择 **Suspend（暂停）**
3. 在确认对话框中：
   - 查看暂停警告信息："Users will not be able to access the system"
   - 在 Notes（备注）字段输入暂停原因（建议填写）
4. 点击 **Confirm（确认）** 执行暂停

也可以从租户详情页点击 **Suspend** 按钮执行相同操作。

#### 暂停效果

- 该租户下所有用户立即无法登录
- 已登录用户的会话将被终止
- 租户数据保持不变，不会被删除
- 租户状态变为 Suspended（暂停）

---

### 激活租户

重新激活一个已暂停的租户，恢复其用户的访问权限。

#### 操作步骤（单个激活）

1. 在租户列表页面，点击目标暂停租户行的操作按钮
2. 选择 **Activate（激活）**
3. 在确认对话框中：
   - 在 Notes（备注）字段输入激活原因（可选）
4. 点击 **Confirm（确认）** 执行激活

也可以从租户详情页点击 **Activate** 按钮执行相同操作。

#### 激活效果

- 租户状态变为 Active（活跃）
- 该租户下所有用户恢复正常登录权限
- 所有功能和数据恢复访问

---

### 批量操作

支持同时对多个租户执行暂停或激活操作，提高管理效率。

#### 操作步骤

1. 在租户列表页面，使用行首的**复选框**选择目标租户
2. 选中后，页面顶部显示批量操作按钮栏
3. 可用的批量操作：
   - **Suspend Selected（批量暂停）**：暂停所有选中的活跃租户
   - **Activate Selected（批量激活）**：激活所有选中的暂停租户
4. 点击批量操作按钮后，系统弹出确认对话框
5. 确认后系统执行操作并显示结果

#### 注意事项

- 每次批量操作最多支持 **100 个**租户
- 不符合条件的租户会被自动跳过（例如对已暂停的租户执行暂停操作）
- 跳过的租户会在结果中列出跳过原因
- 建议先使用"预览"功能确认操作范围

## 常见问题解答（FAQ）

### Q: 如何获取超级管理员权限？

**A:** 超级管理员权限由系统初始化时自动创建。默认的超级管理员账号（superadmin）在数据库迁移时自动建立。如需创建额外的超级管理员用户，需由现有超级管理员在系统租户下创建用户并分配 `SUPER_ADMIN` 角色。

### Q: 忘记了超级管理员密码怎么办？

**A:** 请联系数据库管理员，通过以下方式重置密码：
1. 连接到 PostgreSQL 数据库
2. 找到系统租户（`tenant_id = 00000000-0000-0000-0000-000000000000`）下的超级管理员用户记录
3. 使用正确的 bcrypt 哈希值更新密码字段
4. 更新后使用新密码登录

> **安全提示**：密码重置操作应记录在案，且仅由授权的数据库管理员执行。

### Q: 暂停租户后，租户数据会被删除吗？

**A:** 不会。暂停操作只是禁止该租户下的用户登录和使用系统。所有业务数据（产品、订单、财务记录等）完整保留。激活租户后即可恢复正常使用。

### Q: 为什么我登录后看不到超级管理员面板？

**A:** 可能的原因：
1. **账号不正确**：确认使用的是超级管理员账号（默认 `superadmin`），而非普通管理员账号（`admin`）
2. **权限不足**：确认账号拥有 `SUPER_ADMIN` 角色
3. **URL 错误**：直接访问 `/super-admin/tenants` 检查是否能进入
4. **缓存问题**：清除浏览器缓存后重新登录

### Q: 租户的订阅计划变更后，原有数据会受影响吗？

**A:** 不会。计划变更只影响功能权限和资源配额上限。已有的业务数据不会被删除或修改。但是：
- **升级**：新功能立即可用
- **降级**：如果当前使用量超过新计划的配额上限，租户需要先清理数据再完成降级

### Q: 审计日志可以删除吗？

**A:** 不可以。审计日志采用**追加写入**（append-only）设计，不提供修改或删除功能。这确保了审计记录的完整性和不可篡改性，满足合规要求。日志的保留策略可以在数据库层面配置。

### Q: 批量操作有数量限制吗？

**A:** 有。每次批量操作最多支持 **100 个**租户。如果需要操作更多租户，请分批执行。

### Q: 超级管理员可以看到租户的业务数据吗？

**A:** 不可以。超级管理员只能查看租户的**元数据**（名称、联系方式、配置等）和**使用统计**（用户数、产品数等）。不能直接访问租户的业务数据（订单详情、产品信息、财务记录等），以保护租户的数据隐私。

### Q: 如何查看特定租户的操作记录？

**A:** 在审计日志页面，使用搜索框输入目标租户的 ID（UUID 格式），即可筛选出所有与该租户相关的操作记录。也可以结合操作类型筛选器进一步缩小范围。

### Q: 统计报表的数据是实时更新的吗？

**A:** 关键指标卡片（总租户数、活跃数等）在每次页面加载时实时获取。增长趋势图的数据根据选择的时间范围动态计算。如需查看最新数据，点击页面的刷新按钮或重新加载页面。

### Q: 如何创建多个超级管理员？

**A:** 目前需要通过数据库迁移或直接在系统租户下创建用户来添加额外的超级管理员。步骤概要：
1. 在系统租户（`tenant_id = 00000000-0000-0000-0000-000000000000`）下创建新用户
2. 为新用户分配 `SUPER_ADMIN` 角色（`role_id = 00000000-0000-0000-0000-000000000100`）
3. 新用户即可使用超级管理员功能

## 最佳实践建议

### 账号安全

1. **立即修改默认密码**：首次使用后，立即将默认超级管理员密码修改为强密码
2. **使用强密码策略**：密码长度至少 12 位，包含大小写字母、数字和特殊字符
3. **最小权限原则**：仅在必要时才创建额外的超级管理员账号
4. **定期审计**：定期检查审计日志，确认没有未授权的管理操作

### 租户管理

1. **规范命名**：使用清晰、统一的命名规范为租户命名（如"公司名称-部门"）
2. **合理设置配额**：根据租户实际需求设置配额，避免过度分配或限制过严
3. **及时处理试用到期**：定期检查试用租户，试用到期前与租户沟通转正或延期
4. **暂停而非删除**：对于临时需要停用的租户，优先使用暂停功能而非删除
5. **记录操作原因**：执行暂停、激活、变更计划等操作时，始终在备注字段填写原因

### 订阅管理

1. **合理规划升降级**：了解不同计划的功能和配额差异，为租户推荐合适的计划
2. **关注配额使用率**：定期查看租户的配额使用情况，在接近上限前主动沟通
3. **降级前确认**：降级前确认租户当前使用量不超过目标计划的配额限制

### 监控与审计

1. **定期查看统计报表**：每周至少查看一次统计报表，了解平台运营趋势
2. **关注异常暂停**：监控"最近暂停的租户"列表，确认所有暂停都是计划内的
3. **导出审计日志备份**：定期导出审计日志的 CSV 文件作为离线备份
4. **启用自动刷新**：在需要实时监控时开启审计日志的自动刷新功能

### 日常运维

1. **批量操作前预览**：执行批量暂停/激活前，先检查选中的租户列表
2. **高峰期避免大批量操作**：在业务高峰期避免执行大规模的批量操作
3. **保持通信**：重大变更前（如计划变更、暂停）提前通知受影响的租户
4. **文档记录**：对重要的管理决策和操作，除系统审计日志外，额外在内部文档中记录背景和原因
